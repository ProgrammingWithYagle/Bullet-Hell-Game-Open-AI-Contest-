# Class specialization: next development direction

Status: resumed development, 2026-11-02. The bounded Engineer Free Play pilot is implemented; see [ENGINEER_PATHWAYS.md](ENGINEER_PATHWAYS.md) for actual mechanics, conflicts and limits. The broader pathways, later grades and Campaign teaching below remain proposals. This plan does not finalize all twelve pathway rosters.

## The user's request

Keep the useful existing upgrades, but add another part of the class tree with more fun, dynamic and specialized pathways. The user's concrete Engineer examples are a technology pathway for advanced machinery and a trap pathway for traps. They also want more abilities/upgrades within the grades from D- through SS+, more replay value and a stronger connection between character development and the story.

That direction is accepted. The example designs below are proposals for iteration, rather than an approved final roster of pathways or implemented features.

## What exists

The live catalog has twelve classes, 648 class nodes (54 per class), 48 weapons, 36 ability transformations and two General Free Play purchases. Every class has three parent branches, each with three six-node paths. Their grade lanes cover all eighteen grades: D-, D, D+, C-, C, C+, B-, B, B+, A-, A, A+, S-, S, S+, SS-, SS and SS+.

The current paths mostly extend familiar numerical effects. Some nodes already change abilities, including the three transformations per class and Heavy/Tank shield-cap choices. Preserve those working distinctions. The request is for deeper identities and choices, not merely new names for damage, cooldown and health bonuses. Historical SKILL_TREE_AND_MENU.md / CLASS_TALENTS.md / OPTIONAL_SKILL_MAP.md snapshots contain older seven-class totals; current catalog and the current handoff take precedence.

Campaign uses learned/proven/prepared knowledge, no SP and no mutations. Only the first chapter's D- foundation is implemented. Free Play keeps fast earned SP and mutations. Classic/expanded skill views are presentation choices, not additional progression modes. See STORY_MASTERY_SPEC.md and OPENING_CHAPTER.md.

## Design principles

- Retain shared foundations, then expose a clearly named Specializations section. General abilities keep their own section. Both class-tree views must represent the same authoritative choices.
- A pathway changes decisions: where to stand, what to deploy, what to reserve, how to respond or which targets matter. A name and a percentage bonus are insufficient as its whole identity.
- Offer multiple meaningful options within rank bands. Build breadth can grow while a character remains in an early band. More available nodes need not increase prepared power or speed up promotion.
- Give each path an early affordable identity, later interactions, and a distinctive high-grade culmination. Players should feel a build before the last encounter. Do not require a capstone to make the basic path function.
- Use explicit tradeoffs and limited preparation. A specialized Engineer should not automatically obtain the best traps, best mobile machines and best protective construction simultaneously. Allow deliberate hybrids, with readable opportunity costs.
- Retain the current one-capstone rule and fast-run budget until a tested design justifies changing them. Never add hundreds of choices and silently enlarge the SP budget to purchase everything.
- Active variants should fit the existing input model: a chosen loadout can change a slot's behavior rather than adding an unbounded hotbar. Explain conflicts before purchase/preparation.
- Every class remains useful solo and in a party. Support pathways must not depend on arranged injury, idle allies or farming summoned targets. Bosses stay viable without one required specialization.
- Cooldowns, placement, terrain, warning fairness, ownership, resource limits and cleanup belong to shared authority. The renderer explains outcomes; it does not invent mechanical success.
- Keep late grades meaningful. More D/C options must not promote a new Campaign character to SS+ in a few chapters. A technique's grade, prepared field estimate and a person's reputation are distinct facts.

## Engineer prototype

Recommend starting with Engineer, since the user supplied concrete identities. Build a small playable early-band comparison before filling all eighteen grades or all twelve classes. Use existing turret/barricade/siege behavior as the baseline and preserve issued node IDs and saves.

| Proposed pathway | Distinct decisions | Example future interactions | Costs and limits to test |
| --- | --- | --- | --- |
| Machinery / technology | Invest in a small number of purposeful machines; choose their location, role and operating window | Configure a turret for tracking or a committed firing lane; deliberately redeploy; briefly combine machines into an advanced construct | Finite owned machines, deployment commitment, real cover/target rules, competing configurations and bounded uptime |
| Trapper | Prepare ground, predict an approach, choose when to trigger it | Arming windows, visible trigger zones, linked traps or a chosen remote detonation; useful control on ordinary enemies with explicit boss responses | Finite placed traps, actual trigger ownership, invalid-ground rejection, readable detonation and no permanent boss stun |
| Field works (optional third proposal) | Build useful temporary positions and maintain them under pressure | Select a barricade function or a repair interaction; connect two supported positions | No free permanent defenses, no impossible map closures, shared collision rules, no violation of Hellish shielding/recovery restrictions |

These examples are not mechanics currently present. Do not describe a new heat/scrap resource as implemented, or rename SP into a new Campaign currency. Add a resource only if a concrete action needs it. Machinery must remain distinct from the Summoner's living retinue; Engineer traps must remain distinct from Ranger's fieldcraft.

A useful first delivery is two contrasting early Engineer choices, actual shared effects, readable tree inspection and a repeatable Free Play comparison. Campaign introduction follows with a real teacher/work situation and an owned demonstration, rather than awarding an advanced path in dialogue alone. Kesa Morn and Tamsin Reed can disagree about maintainability and improvisation; their existing branch-specific obligations remain intact. No scene or promotion is authored by this proposal.

## Ideas for the other disciplines

Working vocabulary only; names, branch count and exact abilities can change. These are not twelve additional classes.

| Class | Possible pathway identities | What should feel different |
| --- | --- | --- |
| Soldier | Mobile skirmisher / squad command / field logistics | Repositioned firing, consequential coordinated windows, or careful ammunition and rally placement |
| Heavy | Siege gunner / suppressor / armored anchor | Committed firing lanes, controlled space, or a slower defended operating position |
| Tank | Mobile bulwark / interceptor / bastion | Escort movement, deliberate interception, or construction of a held position; all within actual difficulty limits |
| Medic | Field surgery / rapid response / preventive care | Committed treatment, mobile rescue decisions, or limited advance protection; no injury farming or invented universal cures |
| Mage | Binding / spatial craft / volatile spellwork | Sustained control, position planning, or risk-managed spell interactions; distinct from Alchemist's physical mixtures |
| Assassin | Duelist / infiltrator / mark hunter | Committed single-target openings, movement and concealment tasks, or deliberate target selection; no passive hazard immunity |
| Bard | Conductor / lament / misdirection | Coordinated performance windows, costly sustained influence, or fragile deception; no compulsory rhythm test or copied Fool powers |
| Swordsman | Measured stance / counterstroke / flowing pursuit | Held commitment, carefully limited responses, or movement-linked sword sequences; distinct from Tank protection and Assassin concealment |
| Summoner | Cohort commander / bonded companion / formation keeper | Commanding several finite units, investing in fewer stronger bonds, or arranging protective formations; genuine unit ownership and loss |
| Ranger | Marksman / tracker / field controller | Patient shot planning, information and pursuit, or maintained stakes and cables; distinguish from Engineer machinery/traps |
| Alchemist | Reactive mixtures / prepared compounds / restorative practice | Timing owned combinations, committing recipe stock in advance, or carefully limited care; retain finite ingredients and real useful impacts |

Choose mechanics that reveal different approaches within a shared discipline. Not every practitioner needs a different class. Side characters and antagonists should also have practices, constraints and relationships, rather than exist only to demonstrate the player's next upgrade.

## Same techniques, different acquisition

Free Play: purchase eligible techniques with earned SP, choose an expedition build quickly, and compare distinct builds under known rules. Existing modifications/record exclusions remain explicit. Adding a path does not silently make old nodes unaffordable or alter historical receipts.

Campaign: encounter knowledge through a teacher, observation, manual, research or lived task; learn it, demonstrate a meaningful owned use, then prepare it within the current story band. Money buys equipment and practical supplies, not proof or an arbitrary mastery-point substitute. Relevant failures and ethical disagreements can affect character scenes without erasing learned knowledge. Durable character records and multi-chapter history still need implementation.

Both modes must call the same actual technique definitions and simulation. Authored access, loadout limits and acquisition differ. New story skills, maps, objectives and bosses should gain a sensible Free Play entry. Imported local practice records never become online authority.

## Story use

Let specializations express choices rather than determine a whole personality. Two Engineers may share techniques but disagree about who can repair a machine later; one person may revise their approach after a failure. Civilian expertise and earlier jobs remain valuable without secretly granting a combat rank. Main characters are recent entrants into disciplines practised by many other people.

Use narrator-led physical detail and distinct human speech. Give teachers, peers, human antagonists and bosses independent aims and consequences. Optional personal chapters can explore specialization, but the main cooperative campaign must remain completable without forcing everyone into another character's solo route. Narrative claims must match implemented ranges, limitations, threat levels and grades. No five-million-word plan is complete merely because the tree becomes larger.

## Implementation and acceptance sequence

1. Audit the current Engineer catalog, transformations, authoritative kit, both skill views, old saves and tests. Record which behavior is already implemented; do not start by mass-generating nodes.
2. Define two early pathway identities, their real decision tradeoff, shared technique IDs and availability in each mode. Specify grade/preparation and conflicts separately from numerical field strength.
3. Implement bounded authority behavior and actual costs/cooldowns/ownership/terrain/cleanup. Add readable path inspection and supported inputs. Keep older IDs and deliberate compatibility migrations.
4. Verify useful effects, invalid and repeated inputs, solo/co-op alternatives, owner isolation, death/disconnect/boundary cleanup, pause, late observation and no fabricated proof. Test the real build choices against ordinary objectives and milestone bosses.
5. Introduce Campaign learning only after the ability exists, with explicit provenance and continued slow progression. Extend safe-boundary/checkpoint/journal migration without client-forged online credit.
6. Check the full gate and exact-source CI; freeze matching client/server audiences and run native/network probes within the standing browser restriction. Human/rendered/device/native-language/listening/final-balance acceptance remain separate.
7. Expand horizontally within rank bands, then deepen higher grades as the Campaign's authored milestones support them. Roll out other classes in coherent slices, preserving identity and replay comparisons.

This plan adds no completed-work ledger credit. The game remains unfinished; only the user decides it is complete.
